# CDF workflow deploy artifacts

## ETL workflows (`etl_*`)

Generated by **`python module.py transform build`** (or the operator UI **Build** action) from canvas definitions under **`submodules/transform/workflow_definitions/`**.

Default (unscoped) build writes Toolkit resources flat under this folder:

| File | Cognite resource |
|------|------------------|
| `etl_{id}.Workflow.yaml` | Workflow |
| `etl_{id}.WorkflowVersion.yaml` | WorkflowVersion |
| `etl_{id}.WorkflowTrigger.yaml` | WorkflowTrigger |

Local-run scope documents (not CDF resources) are written to **`workflow_scopes/`**:

| File | Purpose |
|------|---------|
| `workflow_scopes/etl_{id}_scope.yaml` | Trimmed scope document (local run + trigger `input`) |

With **`--scoped`**, Toolkit YAML goes under **`workflows/<scope>/`**; scope documents go under **`workflow_scopes/<scope>/`**.

Authoring sources stay under **`submodules/transform/workflow_definitions/`**. Toolkit **DataSet**: **`data_sets/ds_discovery_etl.DataSet.yaml`**. See **`submodules/transform/docs/BUILD.md`**.

## Inverted-index workflows (`wf_discovery_idx_*`)

Event-driven and scheduled inverted-index workflows use **generated** WorkflowTrigger YAML aligned with **`submodules/inverted_index/default.config.yaml`**:

| File pattern | Workflow | Trigger type |
|------|----------|--------------|
| `trigger_source_metadata_{view}.WorkflowTrigger.yaml` | `wf_discovery_idx_source_metadata_incremental` | `dataModeling` (one view per trigger from `index_field_config`) |
| `trigger_target_driven_{view}.WorkflowTrigger.yaml` | `wf_discovery_idx_target_driven_incremental` | `dataModeling` (one view per trigger from `subscription.watch_view_keys`) |
| `trigger_source_index_watermark.WorkflowTrigger.yaml` | `wf_discovery_idx_source_index_watermark` | `schedule` |

Each `dataModeling` trigger uses a single `with` / `select` key (CDF requires exactly one key in `select`).

**Do not edit** the `trigger_*.WorkflowTrigger.yaml` files by hand. After changing inverted-index config (`index_field_config`, `subscription`, `scope`, etc.):

```bash
python module.py build --build-inverted-index-triggers --force
```

Verify committed triggers match config (CI / pre-merge):

```bash
python module.py build --check-inverted-index-triggers
```

### Toolkit deploy variables

Merge **`submodules/inverted_index/config/inverted_index_deploy.config.yaml`** into project `config.*.yaml` before `cdf build` / deploy (or use module **`default.config.yaml`** defaults). It supplies auth, batching, and watermark cron placeholders only — view external IDs and `dataModelingQuery` branches are generated from runtime config.

Required at deploy time:

- `workflowClientId`, `workflowClientSecret`

Optional defaults:

- `source_metadata_batch_size`, `source_metadata_batch_timeout`
- `subscription_batch_size`, `subscription_batch_timeout`
- `source_index_watermark_cron`
